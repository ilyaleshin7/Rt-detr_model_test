# Проект распознавания дорожных знаков

## Backend MVP для распознавания ограничений скорости на YOLO26

В репозитории реализован минимальный backend MVP на FastAPI для инференса
дорожных знаков по изображениям. MVP использует обученную модель YOLO26:

```text
best_weights/yolo26L_best.pt
```

Корневой файл `main.py` является legacy-экспериментальным скриптом и не
используется как точка входа backend-а. Данный файл был переименован в `main_inference.py`.

### Фокус MVP

Backend является микросервисом поддержки принятия решений для знаков
ограничения скорости в контексте Российской Федерации. Он не реализует
видеостриминг, PyQt UI, Docker или логику автономного вождения.

Только следующие классы модели могут влиять на активное состояние скорости:

```text
forb_speed_over_5
forb_speed_over_10
forb_speed_over_20
forb_speed_over_30
forb_speed_over_40
forb_speed_over_50
forb_speed_over_60
forb_speed_over_70
forb_speed_over_80
forb_speed_over_90
forb_speed_over_100
forb_speed_over_130
```

Все остальные обнаруженные классы игнорируются в логике принятия решения.
Значение `unknown` используется только как внутреннее состояние backend-а.
Это не класс модели.


### Запуск backend-а

```bash

```


### Endpoint-ы

Проверка состояния сервиса:

```bash
curl http://127.0.0.1:8000/health
```

Предсказание по изображению:

```bash
curl -X POST "http://127.0.0.1:8000/predict" ^
  -F "file=@path\to\image.jpg"
```

Endpoint `/predict` возвращает JSON следующего вида:

```json
{
  "detected": true,
  "speed_sign_detected": true,
  "detections": [
    {
      "label": "forb_speed_over_60",
      "confidence": 0.91,
      "bbox": [10.0, 20.0, 120.0, 160.0]
    }
  ],
  "main_sign": "forb_speed_over_60",
  "speed_limit": 60,
  "confidence": 0.91,
  "message": "Ограничение скорости 60 км/ч",
  "state": "known",
  "display_should_update": true
}
```

### Поведение состояния

При запуске активное состояние равно `unknown`, поэтому интерфейс должен
оставаться пустым.

Если обнаружен валидный знак ограничения скорости, backend выбирает
разрешённую speed-limit детекцию с наибольшей уверенностью, но не меняет
активную скорость по одному кадру. Новый active speed-limit sign должен
подтвердиться минимум `REQUIRED_CONFIRMATIONS` раз подряд. Значение по
умолчанию: `2`.

Для смены active state используется отдельный порог уверенности
`MIN_CONFIDENCE_FOR_STATE_UPDATE`. Значение по умолчанию: `0.7`. Детекции ниже
этого порога могут отображаться в preview/bbox, но не участвуют в смене
активного ограничения скорости.

Если новый кандидат ещё не подтвердился, backend продолжает возвращать старый
active state. Pending-кандидат не меняет правую панель UI сам по себе. Pending
сбрасывается, если подтверждение прервано другим speed-limit candidate или
кадром без валидного candidate.

Если валидный знак ограничения скорости не обнаружен, но скорость уже была
известна ранее, backend сохраняет последнюю активную скорость и возвращает
`display_should_update = false`.

Активная скорость сбрасывается только при перезапуске процесса сервиса.

## PyQt UI для отображения текущего ограничения

UI является отдельным клиентом отображения. Он не загружает модель и не
выполняет инференс самостоятельно: изображения и кадры отправляются в backend
через `/predict`, а ответ backend-а используется для выбора PNG из `ui/assets/`.

### Запуск UI

Сначала запустите backend:

```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Затем в отдельном терминале запустите PyQt-клиент:

```bash
python -m ui.display
```

### Проверка backend-а из UI

Нажмите кнопку `Проверить backend`. В статусной строке должно появиться
состояние backend-а, факт загрузки модели и текущее значение `state`.

### Тест изображения

1. Нажмите `Выбрать изображение`.
2. Выберите PNG/JPG/BMP/WEBP-файл.
3. Нажмите `Отправить изображение`.
4. UI отправит файл в `/predict` и обновит знак по ответу backend-а.

### Тест видео

1. Нажмите `Выбрать видео`.
2. Выберите видеофайл.
3. Нажмите `Запустить видео`.
4. `ui/video_client.py` будет читать видео через OpenCV, показывать preview в
   окне и отправлять в backend каждый 5-й кадр.
5. Для остановки нажмите `Остановить видео`.

Во время обработки видео preview-область показывает текущий кадр. На
анализируемых кадрах поверх видео рисуются bbox, подписи классов и confidence.
Preview может показывать все detections, которые backend вернул для отображения,
но правая панель текущего ограничения скорости использует только speed-limit
state backend-а.

В UI доступны параметры обработки видео:

- `Отправлять каждый` — значение `send_every_n_frames`, по умолчанию `5`.
- `Max width кадра` — уменьшение копии кадра перед отправкой в backend. Значение
  `0` означает, что resize не применяется. Preview в UI показывает исходный
  видеокадр, а не уменьшенную копию.

### Сохранение runtime-метрик и журнала событий

После завершения обработки видео нажмите `Сохранить метрики` и выберите папку.
UI сохранит:

- `metrics.json`
- `metrics.csv`
- `events.json`
- `events.csv`

Runtime-метрики доступны для любого видео без разметки:

- `total_frames`
- `analyzed_frames`
- `send_every_n_frames`
- `max_frame_width`
- `avg_inference_time_ms`
- `estimated_processing_fps`
- `total_speed_detections`
- `speed_sign_detected_frames`
- `state_changes_count`
- `unique_detected_speed_classes`

Журнал событий фиксирует события по кадрам: обнаружение speed-limit знака,
изменение активного знака, сохранение предыдущего ограничения, `state unknown`,
завершение или остановку видео.

### Важное ограничение evaluation-метрик

На обычном видео без ground truth разметки нельзя честно считать `mAP50`,
`mAP50-95`, `precision`, `recall` и `F1`. В текущем MVP сохраняются только
runtime-метрики. Будущий evaluation mode должен принимать размеченные данные и
считать quality metrics отдельно от runtime-метрик.

### Правило выбора изображения знака

- Если backend возвращает `state = "unknown"`, UI всегда показывает
  `ui/assets/unknown.png`.
- Если backend возвращает `state = "known"`, UI использует `main_sign` как имя
  PNG-файла, например `forb_speed_over_70` -> `ui/assets/forb_speed_over_70.png`.
- Если `display_should_update = false`, UI не перерисовывает знак без
  необходимости и сохраняет последнее отображённое ограничение.

Проект по обнаружению дорожных знаков с использованием моделей компьютерного зрения на базе Ultralytics RT-DETR / YOLO.

## Описание проекта

Данный проект предназначен для:
- запуска инференса обученной модели на видео;
- оценки производительности модели по времени обработки и FPS;
- валидации модели на датасете;
- вывода основных метрик качества детекции;
- сохранения метрик по классам в CSV-файлы.

На текущем этапе основной рабочий сценарий реализован в файле `main.py`.

## Основной функционал

Файл `main.py` выполняет следующие действия:
1. Загружает обученную модель.
2. Запускает инференс на видео.
3. Считает количество обработанных кадров и средний FPS.
4. Выполняет валидацию модели на датасете.
5. Выводит метрики качества:
   - mAP@0.5
   - mAP@0.5:0.95
   - Precision
   - Recall
   - F1-score
6. Сохраняет per-class метрики в CSV.

## Актуальный датасет

В проекте использовался актуальный датасет:

Traffic Signs Detection Europe  
Roboflow Universe:  
https://universe.roboflow.com/radu-oprea-r4xnm/traffic-signs-detection-europe/dataset/14

Локально в проекте используются актуальные папки датасета:
- `new_dataset_yolo11/`
- `new_dataset_yolo26/`

Также в проекте присутствуют другие папки с данными и результатами, относящиеся к предыдущим этапам работы.

## Структура проекта

Примерная структура проекта:

- `main.py` — основной рабочий скрипт: инференс + метрики + сохранение результатов
- `inference_2.py` — дополнительный/экспериментальный скрипт
- `best_weights/` — лучшие обученные веса моделей
- `pretrained_weights/` — предобученные веса моделей
- `dataset/` — предыдущий датасет
- `new_dataset_yolo11/` — актуальная версия датасета для экспериментов с YOLO11 / RT-DETR
- `new_dataset_yolo26/` — актуальная версия датасета для экспериментов с YOLO26
- `runs/` — результаты обучения/валидации Ultralytics
- `video/` — входные видео для инференса
- `video_results/` — сохранённые результаты обработки видео
- `archive/` — старые и неактуальные файлы, не участвующие в основном сценарии

## Веса моделей

В проекте используются следующие веса моделей:

### Предобученные веса
Файлы предобученных моделей должны находиться в папке `pretrained_weights/`:
- `rtdetr-l.pt`
- `yolo11l.pt`
- `yolo11n.pt`
- `yolo26l.pt`

### Лучшие обученные веса
Финальные обученные веса должны находиться в папке `best_weights/`:
- `rtdetr_best.pt`
- `yolo11L_best.pt`
- `yolo26L_best.pt`

> Если весов нет в репозитории, их необходимо добавить вручную в соответствующие папки перед запуском проекта.
